# Proposal: verification matrix

Boundaries follow [conventions › Testing](../conventions.md#testing). An application is written over several requests, checked against a program's questions and the clock, and kept as versions, so the proposal tests start the full application against PostgreSQL and speak real HTTP. Sign-in goes through the real code flow with the SMTP server replaced; a stored file is a row of `storage_file`, since a save reads the record, never the bytes.

## The screens

`web/tests/e2e/apply.spec.ts` runs on desktop and mobile Chrome with axe. The web server's reads are answered by `tests/e2e/stub-applications.mjs`; what the browser writes is answered by the test, which keeps the application, the organization and the solution between calls. It covers: signing in comes first and returns to the form; the link of an email, opened signed out, asks to sign in and returns to the application; step 1 says beside each field what is missing and focuses the first; a person on their own applies through an organization made from their name; a person who joins their company from step 1 applies for it at once, with what they typed kept and its only solution chosen, and one who asked to join is still asked who applies; the solution is saved and its deck uploaded at once; the program's questions, a file among them and one answered by several choices, a named group of checkboxes that says when none is chosen; the review shows everything, the choices included, and asks for a confirmation before the submission; a step left behind complete says so in the list of steps, and below 640px the program's name stands under the bar of steps; a draft is taken up at the first step that lacks something, its review marks the missing line, holds Submit with the reason and leads to the field; someone who has submitted returns to the review, and a step in the address is respected; a draft's own page leads with where it stands and Continue; the receipt, My applications and an application's page, which reads the choices and the solution's demo link back; withdrawing asks first and sends one command; My applications starts empty and leads to the programs.

`web/tests/e2e/proposals.spec.ts` covers the PDF of a use-case proposal on desktop and mobile Chrome with axe: Open shows the full-screen viewer with every page and the download link on the received proposal (the address `/api/proposal/use-case-proposals/{id}/file`), on the sender's own page (`/api/proposal/use-cases/{useCaseId}/proposal/file`), and in the wizard's PDF step and review right after the upload, from the browser's own copy. The stub answers each with a real three-page PDF (`fixtures/deck.pdf`, through `serveStoredPdf`). `web/src/lib/storage/uploaded-files.test.ts` checks the copy kept of an uploaded file.

Set `APPLY_SHOTS` to a folder to save a screenshot of each step at both widths.

`web/tests/e2e/judging.spec.ts` covers the review on desktop and mobile Chrome with axe, its reads answered by `tests/e2e/stub-judging.mjs` and its writes by the test: an operator narrows the list by tab and decides on several applications at once; scores an application on every criterion, each a radio group the arrow keys move along, with how many are scored and why the save is held said in the panel, reads an answer of several choices, the demo link that opens in a new tab and the judges' scores with their version, and decides; a judge finds their program under Reviews, scores without seeing anyone else's score, has no decision and no admin area; an operator invites a judge and sees the criteria fixed; the release waits for the confirmation and sends both groups' emails.
