# Notification: verification matrix

Boundaries follow [conventions › Testing](../conventions.md#testing). Rendering is pure, so `EmailRendererTest` runs without Spring. Each provider adapter talks to its provider's API, so an adapter is tested against a server that answers as the provider documents; the Resend and Brevo adapters' base addresses are settings, and the SES client has no endpoint to point at a stub, so the SES setup checks have no test. The administration, the queue and the delivery reports are the filter chain, the controllers, the services and PostgreSQL, so `EmailAdministrationTest` starts the full application and speaks real HTTP; only the SMTP server is replaced, by GreenMail (`TestMailbox`), which every HTTP test class imports for the mail it reads. That the sign-in code and the other kinds are sent is covered where they are asked for, in the [identity](identity.md), [organization](organization.md), [proposal](proposal.md) and other matrices.
