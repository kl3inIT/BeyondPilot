# Messaging: verification matrix

Boundaries follow [conventions › Testing](../conventions.md#testing). `MessagingTest` starts the full application against PostgreSQL and speaks real HTTP, signing in through the emailed code as the identity tests do; only the SMTP server is replaced, which is how it reads the emails. It listens to the events through `MessagingService.events`, the stream the controller carries. What the screen makes of the lists and of what it hears is plain code, tested in `web/src/features/messaging/messaging-state.test.ts`.

| Contract                                                                                                                                                                                                                                                               | Regression it catches                                                                                   |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| A first message to a person waits: it is under their requests and the sender's chats, nobody writes in it, the person is emailed without the sender's address and led to Messages (`aFirstMessageToAPersonWaitsUntilTheyAcceptAndThenBothWrite`)                       | A message that reaches someone who did not agree; an address in an email; a request nobody can find     |
| An acceptance opens the conversation once, emails the sender and is audited; a second answer is refused (same test)                                                                                                                                                    | Two answers to one request; an acceptance nobody hears of                                               |
| What the other side wrote is unread until the reader says how far they read, and the writer then sees how far it was read (same test)                                                                                                                                  | A count that never clears; "Seen" that lies                                                             |
| Reading a request tells its sender nothing; a reader is never recorded past the last message; spaces of another script are no message (same test)                                                                                                                      | "Seen" under a request nobody accepted; "Seen" on messages not yet written; a `500` for a blank message |
| Writing again to a subject the caller talks with goes into that conversation (same test)                                                                                                                                                                               | Two conversations with the same people about the same thing                                             |
| A message sent twice under one identifier is written once; another person cannot take the identifier (`aMessageSentTwiceIsWrittenOnceAndAnotherPersonReadsNothing`)                                                                                                    | A retry that doubles a message; a message attributed to someone else                                    |
| A person on neither side reads, writes and marks nothing, and gets `404` as for a conversation that does not exist (same test)                                                                                                                                         | A conversation read by guessing its identifier                                                          |
| A decline and a report read the same to the sender, are gone for the side that answered, and the sender may write again; operators read what was reported, with who sent it, and only they (`aDeclineAndAReportReadTheSameToTheSenderWhoMayWriteAgain`)                | A report that exposes who reported; a declined sender locked out for good; a report nobody reads        |
| A first message is refused to an unknown address, to the caller's own profile or organization, by a person without an approved organization to a provider, and when empty (`aFirstMessageIsRefusedWhenItCannotBeWritten`)                                              | A conversation with oneself; a provider written to by nobody they can name                              |
| A solution its owners keep out of the directory is still written to by its address (`aSolutionLeftUnlistedIsStillWrittenToByItsAddress`)                                                                                                                               | A provider nobody can reach once they leave the directory                                               |
| A conversation with a provider is read and written by every member, each message naming its side; only an owner answers the request; a colleague's message is not unread for the organization (`aConversationWithAProviderBelongsToItsOrganizationAndItsOwnersAnswer`) | A request a member accepts for the company; a conversation one employee holds alone                     |
| A conversation with GenAI Fund about a published program is open at once and is every operator's; an operator does not write to GenAI Fund (`aConversationWithGenAiFundAboutAProgramIsOpenAtOnceForItsOperators`)                                                      | A question to GenAI Fund that waits for nobody                                                          |
| A screen hears that someone writes, the message, and the read, in that order, each as its listener reads it; a person outside the conversation hears nothing; a listener is not emailed (`aScreenThatListensHearsWhatIsWrittenReadAndTypedInItsConversationsOnly`)     | A message told to the wrong person; a person emailed about what is on their screen                      |
| A person with no screen open is emailed once until they read, without the text, and again for what comes after (`aPersonWithNoScreenOpenIsEmailedOnceUntilTheyRead`)                                                                                                   | An email for every message; a message nobody learns of                                                  |
| A request is reminded once after seven days and closed after fourteen, which the sender is told; it is then gone for the other side and the sender may write again (`aRequestNobodyAnswersIsRemindedOnceAndThenCloses`)                                                | A reminder every hour; a request that waits forever                                                     |
| The eleventh conversation in a day is refused with `429` and `Retry-After` (`aPersonStartsOnlySoManyConversationsInADay`)                                                                                                                                              | One sender writing to the whole directory                                                               |
| Every path needs a session (`everythingNeedsASession`)                                                                                                                                                                                                                 | A conversation read by a visitor                                                                        |
| A message heard moves its conversation to the top and counts as unread unless the reader looks at it; one from the reader's own side does not count (`messaging-state.test.ts`)                                                                                        | A list that does not follow the newest message; a count for one's own colleague                         |
| A message the reader sends is shown at once, last, takes its place when kept, is shown once when also heard, and says when it did not arrive (`messaging-state.test.ts`)                                                                                               | A sent message that jumps, doubles or silently disappears                                               |
| How far the other side read never moves back; reading on another screen clears the count; "is writing" ends when the message arrives (`messaging-state.test.ts`)                                                                                                       | "Seen" that goes away; a count that stays after reading elsewhere                                       |
