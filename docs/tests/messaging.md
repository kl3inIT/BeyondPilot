# Messaging: verification matrix

Boundaries follow [conventions › Testing](../conventions.md#testing). `MessagingTest` starts the full application against PostgreSQL and speaks real HTTP, signing in through the emailed code as the identity tests do; only the SMTP server is replaced, which is how it reads the emails. It listens to the events through `MessagingService.events`, the stream the controller carries. What the screen makes of the lists and of what it hears is plain code, tested in `web/src/features/messaging/messaging-state.test.ts`.

Program assignment regression coverage verifies metadata without messages or sender details, refusal before assignment, assignment and reassignment, live event exclusion for unrelated and revoked operators, and an audit record for each assignment.

`admin-messages.spec.ts` verifies operator-only assignment management, short Chat assignments labels, and the removed reported-message page and API returning 404.

The header message shortcut is covered by `header-messages.test.tsx`: its destination, no badge at zero, unread messages plus pending requests, "99+" above 99, refresh each minute after receiving and reading, retaining the last count during a failed request, and refreshing after focus or visibility returns.
