# Program: verification matrix

Boundaries follow [conventions › Testing](../conventions.md#testing). An operator's change is an HTTP request, a row, its lists and an audit event, and a visitor's read depends on the session and the clock, so the program tests start the full application against PostgreSQL and speak real HTTP. Sign-in goes through the real code flow with the SMTP server replaced. Where a program stands is a function of its dates and a moment, so its boundaries are a unit test.

## The admin screens

`web/tests/e2e/admin-programs.spec.ts` runs on desktop and mobile Chrome with axe; the programs a page reads on the web server are answered by `tests/e2e/stub-backend.mjs`, and the commands the browser sends by the test, which checks the CSRF header on each. The browser runs in Paris, so a time written or sent in another zone than Vietnam's shows. It covers: nobody but an operator gets the list or a program's Settings; the list shows each program's state and window, in Vietnam time; New program suggests the address from the name, Vietnamese included, sends the three members and opens the draft's Settings; a taken address is told beside the field; a draft lists what blocks publishing, each line focusing its field, and Publish becomes Save and publish once something changed; a save sends the whole program with its window and key dates as instants of Vietnam time; dates out of order are refused before anything is sent; someone else's save in the meantime is told above the form; a published program's address is locked; unpublishing and Save and publish each ask first, show the address, and send one command; an operator adds questions in a dialog and saves them together, and the questions of a program whose applications are open are shown as fixed.

Unit tests beside the code cover the address made from a name (`program-schemas.test.ts`), the program as Settings holds it and as it is sent back (`program-values.test.ts`), the days and times of Vietnam (`lib/vietnam-time.test.ts`) and the field a validation problem points at (`lib/api/problem-fields.test.ts`).

Checked by hand on the local stack on 5 October: a cover uploaded to the local store and shown in Settings, a program saved, a refused save, publishing a new program after filling what blocked it, and unpublishing it.

## The public pages

`web/tests/e2e/programs.spec.ts` runs on desktop and mobile Chrome with axe, the programs answered by `tests/e2e/stub-backend.mjs` with dates counted from the moment it starts. It covers: the list shows what is open now with its countdown and Apply, what is coming up (programs not started and events still to come) and what is done, and never a draft; a program whose page is somewhere else links there; the phase tabs and the type are the address; a standard page shows the program, its About and its timeline, and no use case section when none is attached; the Tasco page is the one made for it, its timeline taken from the program, the use cases attached to it listed and named in its navigation, its card to apply before the challenge on a phone, and its Vietnamese copy at `/vi`; a draft answers 404 to a visitor and shows an operator a banner that leads back to Settings; an unknown address is not found.
