# Use case: verification matrix

The public directory and detail include expired approved/published briefs, never expired drafts, in-review or needs-changes records. `UseCaseAdministrationTest.onlyPublishedUseCasesRemainPublicAfterClosingAndPaginationCountsThem` verifies the two-page result, totals, availability filters, invalid filters and private detail refusals. Proposal late-write guards remain covered by `UseCaseProposalTest`; expiry does not grant new submission rights.

`proposal-actions.test.tsx` verifies that expired guest/new/draft/withdrawn/refused submission paths render a disabled deadline control, while sent and posting organizations keep their respective view links. No deadline still offers sending. `use-cases.spec.ts` checks the status's position with the deadline below the budget/timeline, the full-opacity disabled danger control in English/Vietnamese, readable expired briefs, paging and accessibility in desktop/mobile browsers.

Boundaries follow [conventions › Testing](../conventions.md#testing). An operator's change is an HTTP request, a row, its lists and an audit event, so the use case tests start the full application against PostgreSQL and speak real HTTP. Sign-in goes through the real code flow with the SMTP server replaced.

## The organization's screens

The tab, the wizard with its autosave, the read-only page and the sent page are checked by `pnpm check` (types, lint, messages) and by the unit tests of the draft's conversion to the request and of what is still missing (`use-case-draft.test.ts`). Checked by hand on the local stack against the Figma frames before release; `web/tests/e2e/use-case-wizard.spec.ts` covers the attachments on desktop and mobile Chrome with axe: a PDF among them opens in the full-screen viewer in the requirements step and in the review (`/api/usecase/mine/{id}/attachments/{fileId}`), and any other kind is only named. `use-case-attachment-files.test.ts` checks which files can be opened and where they are read.
