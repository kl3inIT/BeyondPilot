# Search: verification matrix

Boundaries follow [conventions › Testing](../conventions.md#testing). Matching is PostgreSQL's work (the unaccented, weighted vector, prefixes and trigram similarity), so the index is tested against PostgreSQL through its repository. The index is fed by events after an operator's commit, so the whole path starts the full application, changes a program over real HTTP and waits for the result a visitor reads without a session.

## The search page

`web/tests/e2e/search.spec.ts` runs on desktop and mobile Chrome with axe, the results answered by `tests/e2e/stub-search.mjs`. It covers: the All tab shows the best three of each kind, the kinds in the order of their best result, with "See all" leading to a kind's tab; the matched word is in bold and a snippet is read as text, never as markup; each kind's row shows its facts (a program's phase and days and a page elsewhere, a solution's organization and customer cases, a person's role and country); a kind's tab lists that kind and leads to its directory with the query; a query that finds nothing hides the tabs and offers queries to try and the directories; without a query the page asks for one, a new query starts on the All tab, and the field clears; on a phone nothing overflows. `home.spec.ts` checks that the landing's search leads to the results. `search-snippet.test.ts` covers how a snippet is split into matched words and text.

Not covered by a test: the nightly schedule itself; the repair it runs is the one the test calls, and the same repair runs when the application starts.
