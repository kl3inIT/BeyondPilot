# Matching: verification matrix

Boundaries follow [conventions › Testing](../conventions.md#testing). What code makes of a model's answer is plain code and is tested without a model or a database. What is kept is PostgreSQL's work and is tested through the repository. A whole run is tested against PostgreSQL with the organization, the solution and the use case made over HTTP the way people make them, and the model played by the JDK's `HttpServer`; no test calls a real provider.

| Contract | Regression it catches | Test |
| --- | --- | --- |
| A quote is found whatever its spacing and case, traced to another source when the model misnames it, accepted when most of its words are there, and refused when it is nowhere | A real quote refused for a line break; an invented quote accepted | `JudgmentRulesTest.aQuoteIsFoundWhateverItsSpacingAndCaseAndIsTracedToAnotherSourceWhenTheModelMisnamesIt` |
| Every required capability met is Direct; an invented quote lowers its finding and the group with it, and its reason is dropped; a constraint and an optional capability never count; what the product is made for is kept and decides nothing | A candidate recommended on words its material does not hold; a reason shown for a finding code refused | `JudgmentRulesTest.everyRequiredCapabilityMetIsDirectAndAnInventedQuoteLowersItsFinding` |
| Technology needs a capability shown or half of them met; the technology alone is no group | A solution recommended only for the tool it is built with | `JudgmentRulesTest.theTechnologyGroupNeedsACapabilityShownOrHalfOfThemMetAndNothingShownIsNoGroup` |
| A requirement is kept only with a known kind and a quote the brief holds, capabilities first | A requirement the model made up; a finding that names the wrong requirement | `JudgmentRulesTest.aRequirementIsKeptOnlyWithAKnownKindAndAQuoteTheBriefHoldsCapabilitiesFirst` |
| A solution without deck or website text says which is missing | "Not shown" reported for lack of text without saying so | `JudgmentRulesTest.aSolutionWithoutDeckOrWebsiteTextSaysWhichIsMissing` |
| A use case has one open run; the worker takes runs oldest first, a waiting run only when its time has come; what a stopped application left running is queued again | Two runs of one use case judging at once; a run lost at a restart | `MatchingRepositoryTest.aUseCaseHasOneOpenRunAndTheWorkerTakesRunsInTheOrderTheyWereQueued` |
| A step adds what each pass judged and keeps what the last pass of the others gave | The cost of a run that continued counted once | `MatchingRepositoryTest.aStepAddsWhatEachPassJudgedAndKeepsWhatTheLastPassOfTheOthersGave` |
| Requirements are replaced together with what they were read from | Requirements of two briefs mixed | `MatchingRepositoryTest.requirementsAreReplacedTogetherWithWhatTheyWereReadFrom` |
| A later run takes out the candidates it no longer finds and keeps those a person decided on | A shortlisted candidate removed by a run | `MatchingRepositoryTest.aLaterRunReplacesTheCandidatesItNoLongerFindsAndKeepsThoseAPersonDecidedOn` |
| Publishing a use case queues its run; the run keeps the requirements whose quote the brief holds, judges the candidate, lowers the invented finding and records each call; a second run of the same brief and material asks nothing; a run that meets the provider's limit waits, keeps what was judged, and then judges only what changed | A run that nobody started; a model's invention shown as a reason; a rerun that pays for the same answers; a run lost at the provider's limit | `MatchingRunTest.aPublishedUseCaseIsMatchedOnceAndARunThatMeetsTheProvidersLimitWaitsAndGoesOn` |
| A run waits for the use case to stay unchanged, a person starts it at once, and no more runs start in a day than operators allow, while a run that started goes on | A run on a brief still being written; a day's cost without a ceiling; a run stranded by the ceiling | `MatchingRepositoryTest.aRunWaitsForItsMomentAndForTheDaysLimitAndAPersonCanStartItAtOnce` |
| The limits are kept only when nobody changed them meanwhile | Two operators overwriting each other | `MatchingRepositoryTest.theLimitsAreKeptOnlyWhenNobodyChangedThemMeanwhile` |
| A candidate is what people last decided, and what an operator added by hand is kept apart | A removed candidate shown as shortlisted; a solution added twice | `MatchingRepositoryTest.aCandidateIsWhatPeopleLastDecidedAndAnOperatorsHandIsKeptApart` |
| Over HTTP: a member of the use case's organization reads the candidates with their reasons and nothing of the cost, a stranger is told there is no such use case, an operator sees the steps; a member shortlists, removes with a reason and restores, but not what GenAI Fund removed; an operator adds a solution by hand and it is judged; a member starts as many runs as a day allows and never has all judged again; the limits are the operators' and each decision is in the audit log | A vendor reading who else was matched; a member undoing GenAI Fund's decision; a member spending without limit | `MatchingRunTest.aPublishedUseCaseIsMatchedOnceAndARunThatMeetsTheProvidersLimitWaitsAndGoesOn` |
| The Matched solutions page derives from one answer: the things asked for are the capabilities, each with a short name and its statement in full; a solution the AI put in no group is left out and one not read yet is kept; the sentence above the list counts what a run recommends and how many of them are a strong fit, and counts nothing removed or in no group; a thing asked for is covered when a recommended solution shows it, and counted for those that show it or part of it; the last group folds to its header, opens to five rows and then to all, and the other groups never fold; a row says whether the one thing asked for is shown only when its group does not say so; an unread deck or website is named; a source reads as profile, customer case, deck page or website | A constraint counted as a thing asked for; a rejected solution shown or counted; a removed solution covering a need; a strong fit hidden behind Show more; a row repeating its group; an unknown source shown as it came | `web/src/features/matching/matching-view.test.ts` |
| In a browser, on desktop and on a phone with axe: a member reads the groups as named regions under second-level headings with what each means, a row with the AI's sentence and no quote, and one solution in full, beside the list or in a sheet, with the statement, the verdict in words, the AI's reason, the vendor's words and their source, and the constraints behind a disclosure; a use case that asks for one thing reads one sentence and no filter, and its last group opens to five rows and then to all; a thing asked for narrows the list; Add to shortlist and Not a fit with a reason send what the backend expects and show its answer; the Removed tab is the one selected, has no panel, says who and why, and a member cannot restore what GenAI Fund removed; a member is asked before a run and told it uses one of the day's runs; an operator is not asked, and finds Add one by hand and Re-review every solution in the More menu, which is checked with axe while open | A page that reads but cannot decide; a reason not sent; a member spending a run by a stray click; a member offered an operator's action; words on the page that no longer match the catalog | `web/tests/e2e/matching.spec.ts` |

The search that finds the candidates is in the [search matrix](search.md).

Not covered by a test: the Matched solutions page while a run is open or failed, without a model, and before the first run; the page in Vietnamese; the 44px touch targets; the Undo of a removal; reading the pages of a file attached to a use case (the page reader is covered in the [AI matrix](ai.md)); the worker's schedule itself, since the test takes each run; four judgments at a time; the quality of the wording itself, which no test with a played model can show: it is measured on real use cases through the real provider ([prompt research](../research/2026-10-09-matching-judge-prompts.md)).
