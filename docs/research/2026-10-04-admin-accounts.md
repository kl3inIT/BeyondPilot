# Admin: the Accounts screen

Written on 4 October 2026, before drawing the operators' Accounts screen (BEY-48). What other products do with a list of people who can sign in, where each has a role and can be switched off, and what was taken from them. The screens were read from Mobbin's captures, at 768px previews except Tailscale's; short strings may be slightly off. The drawn screens are in the Figma file, section `Admin — Accounts (draft for review)`.

## What the screen has to do

List every account that has signed in, with its email, optional name, platform role (`user` or `operator`), status (`active` or `disabled`), last sign-in and creation time; find an account by name or email; filter by role and status; disable and re-enable an account; grant and withdraw the operator role. There is no invitation, no password and no organisation column yet.

Code read in the reference clones under `.tmp/`:

- Medusa admin, `packages/admin/dashboard/src/routes/users`: columns Email, First name, Last name, Created, Updated; a row opens a detail page; delete is confirmed by typing; there is no disabled state, only delete, and a role is set at invitation only.
- Payload, `packages/ui/src/views/List` and the website template's `Users` collection: a generic list with search, page size and bulk selection; the only account state is the lock after failed sign-ins.

Neither models a role together with a disabled status; they informed table mechanics and wording, not this screen's shape.

## What the products agree on

- **Order of columns:** the person, the role, the status, the dates, the menu.
- **The person cell:** avatar, name over a muted email. Without a name, the email takes the first line.
- **Role and status never carry equal weight.** One is a badge or a select, the other plain text or a dot and a word.
- **Search on the left above the table, filters as selects to its right.** The alternative, status tabs, suits products with an "invited" state, which this one does not have.
- **A row menu, with the destructive item last, red and after a divider.** An item that opens a dialog ends with an ellipsis.
- **Switching an account off is confirmed in a dialog** that names the person, says what stops and says it can be undone. Typing to confirm appears only for deleting one's own account.
- **One's own row** carries a "You" marker and loses the control instead of explaining why.
- **This amount of data stays in the table.** A detail page or a drawer appears where a user has more attached: devices, apps, projects.
- **On a phone, native apps stack rows.** Mobbin's web captures are desktop only, so no web reference for 390px was found.

## Not found

- A data table that shows a disabled account beside active ones without a filter; only simple lists do (Trello).
- A confirmation for withdrawing a role; only grants and generic role changes were found, so the withdrawal dialog is this project's own wording.
- A product that says in words why one's own row cannot be changed.
- How these lists page once they are long: the captures hold one to five rows.
