# MCP servers behind OAuth: clients, Spring and MemoryOS

Research for [BEY-78](../increments/active/bey-78-mcp/design.md), 7 October 2026. Three passes: what the MCP clients require (their live documents and docs, fetched that day), what the authorization server inside Spring Security 7.1.1 provides (read at source level from `spring-security-oauth2-authorization-server` 7.1.1), and how MemoryOS and other Spring applications run an MCP server behind OAuth.

The MCP specification of 2025-11-25 makes CIMD a SHOULD and DCR a MAY for the authorization server, requires RFC 9728 protected resource metadata and an exact audience check on the server, and requires rotated refresh tokens for public clients. The revision of 2026-07-28 deprecates DCR with a 12-month window and asks the authorization server for `iss` (RFC 9207). Spring AI 2.0.1 and the MCP Java SDK 2.0.1 speak 2025-11-25.

Sources: [OpenAI Apps SDK authentication](https://developers.openai.com/apps-sdk/build/auth), [Claude connector authentication](https://claude.com/docs/connectors/building/authentication), [Codex MCP](https://learn.chatgpt.com/docs/extend/mcp?surface=cli), [Cursor MCP](https://cursor.com/docs/context/mcp), [MCP authorization 2025-11-25](https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization), [MCP changelog 2026-07-28](https://modelcontextprotocol.io/specification/2026-07-28/changelog).

## What Spring Security 7.1.1 provides

The authorization server now ships in Spring Security (`spring-security-oauth2-authorization-server` 7.1.1; Boot starter `spring-boot-starter-security-oauth2-authorization-server`), configured with `http.oauth2AuthorizationServer(...)`.

| Need                                           | In Spring                                                                                                                                     | Left to us                                                                                                                                                                                  |
| ---------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| DCR (RFC 7591), open                           | `clientRegistrationEndpoint(c -> c.openRegistrationAllowed(true))`; the chain must also permit `POST` on the registration endpoint            | A scope converter: the default validator refuses any `scope` in the request and a client registered without scopes cannot ask for ours                                                      |
| CIMD                                           | Not native (spring-security#18375 open)                                                                                                       | Resolve the document with Nimbus `oauth2-oidc-sdk` (`ClientMetadata.parse`), only from trusted hosts, and keep the client in the database so `findById` still finds it after a cache expiry |
| `private_key_jwt`                              | Native: the client's `jwkSetUrl` and signing algorithm                                                                                        | Map ChatGPT's `jwks_uri` when its document is resolved                                                                                                                                      |
| PKCE S256, consent page                        | Native; `consentPage("/…")` and a real form POST back                                                                                         | The consent page in the web app                                                                                                                                                             |
| Refresh tokens for public clients              | Refused in two places (`OAuth2RefreshTokenGenerator`, `PublicClientAuthenticationConverter`)                                                  | A generator and a converter that allow them, with `reuseRefreshTokens(false)` for rotation                                                                                                  |
| `resource` (RFC 8707) to `aud`                 | Kept in the request but not used                                                                                                              | An `OAuth2TokenCustomizer` setting `aud` from `resource` or, without it, from the scope                                                                                                     |
| `iss` on the authorization response (RFC 9207) | Not found                                                                                                                                     | The authorization response handler adds it; the metadata advertises it                                                                                                                      |
| Loopback redirects                             | `127.0.0.1` and `::1` on any port                                                                                                             | `localhost` on any port (mcp-security's `LocalhostWildcardPortValidator`)                                                                                                                   |
| Protected resource metadata (RFC 9728)         | Native: `oauth2ResourceServer(...).protectedResourceMetadata(...)`, one document per path, and `resource_metadata` in `WWW-Authenticate`      | Nothing                                                                                                                                                                                     |
| Storage                                        | JDBC services; DDL in the jar (`oauth2-authorization-schema.sql` and two more), `blob` to `text`, `timestamp` to `timestamptz` for PostgreSQL | Indexes on the token columns; Jackson mixins for our principal types, which the authorization stores                                                                                        |

spring-ai-community `mcp-security` 0.1.14 (`mcp-authorization-server`) wraps open DCR, CIMD, the localhost validator and a `resource`-to-`aud` customizer for JWTs, and is built on Boot 4.1 and Spring AI 2.0. It is a community 0.1.x line: issue #111 (SSRF in its CIMD URL check) closed on 30 September 2026, #85 (refresh tokens for public clients) is open. Its pieces are taken where they save work; its configurer is not required.

## How other authorization servers implement CIMD

Read at source level on 7 October 2026 (clones under `.tmp/cimd-study`):

- **Fetching.** node-oidc-provider checks the address actually connected to against IANA's special-purpose lists, after DNS, because an upfront lookup is open to DNS rebinding (`lib/helpers/fetch_request.js`); better-auth resolves once, requires public answers and connects to them (`packages/cimd/src/node.ts`); Cloudflare's `workers-oauth-provider` relies on its platform's strictly-public fetch. All refuse redirects and cap the body at about 5 KB with a 2.5 to 10 second timeout. spring-ai-community `mcp-security`, the one Spring implementation, has no address check, size or time limit, so BeyondPilot does not use its resolver.
- **Hosts.** node-oidc-provider, Cloudflare and Logto accept any HTTPS host; Keycloak requires a trusted-domain list. better-auth can require fields on the document's origin and leaves redirects out by default; Keycloak can require one trusted domain for both.
- **Caching.** Cache-Control is honoured within bounds everywhere (node-oidc-provider 30 seconds to a day, Keycloak 5 minutes to 3 days); better-auth also limits fetches per origin. None remembers an address that could not be read.
- **Consent.** Cloudflare gives the page the client host, the redirect host and a loopback flag, noting that any local process could be listening (`oauth-consent.ts`); Logto never approves a CIMD client without asking (`koa-auto-consent.ts`); Keycloak always asks and names the host. None treats a loopback redirect differently when deciding to skip consent, and none has a shared client for local tools.

## What MemoryOS and other Spring applications do

MemoryOS runs its MCP endpoint in process with Keycloak 26.8 as the authorization server and CIMD: Claude connected on 1 October 2026, ChatGPT on 2 October (MemoryOS repository, `docs/decisions/0024-mcp-endpoint-in-process-with-the-members-access.md`). It chose Keycloak because it already had it. What applies without Keycloak: a bearer-only, stateless chain for `/mcp` with an exact-audience decoder and a 401 carrying `resource_metadata` and `scope`; CIMD admitted only from trusted hosts (`claude.ai`, `claude.com`, `chatgpt.com`), which also closes SSRF; grants that lapse after 30 days unused and end after 180; a revoke page for members; a 400 `-32000` answer to unknown protocol versions so ChatGPT falls back; MCP SDK 2.0.1 so `resources/list` gets a JSON-RPC error; `tool-callback-converter: false` so no `ToolCallback` bean of the application leaks onto the server; activity logged without arguments, kept 90 days.

The Spring samples (mcp-security, spring-ai-recipes, Spring blog posts by Daniel Garnier-Moiroux of 2025) run the authorization server as a separate application with form login. No public Spring project was found that runs the MCP server and the authorization server in one application with Claude or ChatGPT connected, so the real clients are tested on staging.
