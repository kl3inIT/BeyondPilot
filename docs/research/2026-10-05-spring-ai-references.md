# What two Spring AI reference repositories teach directory search and MCP

Written on 5 October 2026 for BEY-21. Two public repositories were read to see how Spring AI does hybrid search, reranking, judging and MCP servers. Both use Spring AI 2.0.1 on Spring Boot 4.1, the backend's version, so their code transfers without porting. Nothing was run; every finding is from reading source. Both are cloned under `.tmp/`, and paths are relative to each repository.

- [habuma/spring-ai-recipes](https://github.com/habuma/spring-ai-recipes) at `c9aca38` (1 October 2026): one small application per recipe.
- [tzolov/voxxeddays2026-demo](https://github.com/tzolov/voxxeddays2026-demo) at `03baf7f` (3 October 2026): a conference walkthrough from system prompts to agents, with a web inspector of model traffic.

The question behind the reading: how the search on the home page and in the directory should work, whether it needs a chatbot or a separate search engine, and what the Phase 2 MCP server will need. The scale that decides is about 2,500 solutions and 200 use cases (BEY-21).

## Not adopted

- **Rewriting or expanding the query with a model before every search** (`RewriteQueryTransformer`, `MultiQueryExpander`, HyDE in `hyde-rag/`). Each adds one or two model calls to every search, too slow for a box that searches as the person types. For matching, the use case is already a long text and its own card is embedded.
- **TypeSafe Jev ("systemOne")**, the classifier behind the voxxeddays guardrails, judges and document filters (`spring-ai-typesafe` 0.4.0, a hosted service with its own API key). Search generates no text, so there is nothing to guard, and reranking every search through another vendor adds latency, cost and a new recipient of the data. It may be measured later for screening web research, if the relevance set shows the need.
- **A semantic cache in Redis** (`semantic-caching/`). It caches whole model answers; search needs only the embedding of a repeated query, which an in-memory cache holds.
- **Guardrail advisors** (`SafeGuardAdvisor`, `JevGuardrailAdvisor`) and **chat memory**: they belong to a chatbot. The brief asks for search and recommendations, and in Phase 2 the person's own assistant is the chat, through MCP.
- **Lucene or a search engine beside PostgreSQL.** At this scale PostgreSQL full-text search, pgvector and facet filters in one query are enough, and the search documents stay in the same transaction as their sources.
- **Spring AI's `PgVectorStore`.** It owns its table shape; the planned search document carries facets, a listed flag and one embedding per field.
- **Spring AI Inspector**, a local debugging UI for model traffic. Useful while tuning prompts on a workstation, not part of the application.
