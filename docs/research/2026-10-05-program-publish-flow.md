# Admin: creating and publishing a program

Written on 5 October 2026, before drawing how an operator creates a program, sees it before anyone else, takes it live and takes it down (BEY-29). The Settings screen approved on 4 October draws only a published program: a badge, View page and Save changes. Nothing draws the draft, the way to publish it, or the way back. The screens were read from Mobbin's captures at 768px previews; short strings may be slightly off. The open-source projects were read from shallow clones in the git-ignored `.tmp/` folder on the same day; paths below are relative to each repository.

## What the flow has to do

An operator creates a program, fills it in over several sittings, looks at its page, publishes it, and corrects it later. Publishing for the first time fixes its address, because links to it are then shared ([program design](../increments/completed/bey-29-program/design.md)). A program that turns out wrong is taken off the public site and put back. Later, a program will hold applications, and taking it down must not lose them.

## What recurs

1. **Create small, then fill in.** A dialog with the name and the address (indico, Cal.com, Dub) opens the full settings. The wizards (pretix, pretalx, Eventbrite) are for products where the steps depend on each other, such as tickets before payment.
2. **The address is derived from the name and shown with its prefix.** Event platforms lock it early and say so beside the field; content tools let it be unlocked.
3. **Going live is an action of its own, not a field saved with the form**, named "Publish" or "Go live", and confirmed in a sentence that says who will see what.
4. **What blocks publishing is a list the server computes**, each item a sentence that leads to the field. The button is disabled while the list is not empty, and the server checks again when the button is pressed. Recommendations, when there are any, are kept apart from what blocks.
5. **Before publishing, the organizer sees the real page because they are signed in**, under a banner saying it is not public. No product read uses a secret link.
6. **A change to a live event is live when it is saved.** Only Payload keeps a draft beside the published version, and pretalx only for its schedule.
7. **Taking it down is easy, reversible and keeps the data**, confirmed in one sentence. Deleting is separate and refused once people have registered.
