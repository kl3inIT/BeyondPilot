# Search: one index over programs, solutions and talent

Status: proposed on 6 October 2026 for review ([plan](plan.md)). Tracked in Linear as BEY-65. It builds the search index that the [Phase 1 domain model](../bey-22-phase-1-domain-model/design.md) gives to `matching`, and the `/search` page drawn in Figma on 6 October (section "Search — results (draft for review)"). The research behind it: [search over several kinds of item](../../../research/2026-10-06-search-references.md) and [Spring AI references](../../../research/2026-10-05-spring-ai-references.md).

## What a person can do

- A visitor types in the hero search, or follows one of its chips, and lands on `/search?q=…` with everything public that matches: programs, AI solutions and AI talent in one ranked list, grouped by kind on the All tab, each kind with its count.
- A tab narrows the list to one kind; a link beside it opens that kind's directory with the same query, for the filters only a directory has.
- A misspelt or unaccented query still finds its match: "viet nam" finds "Việt Nam", "agentc" finds "Agentic".
- A search that finds nothing says so and offers the popular searches.
- An operator approves, edits, lists, unlists, publishes or takes down an item, and search shows the change within seconds without anyone acting.
- Use cases join when their public listing exists. Embeddings, meaning-based ranking and the operators' Search and AI screen follow in the AI slice described below.

## Boundary discovery

**Story.** An operator approves the solution "AI Voice & Chat Agent" of Revve AI. Within seconds a visitor who searches "voice agent" sees it under AI solutions, beside Revve AI's founder under AI talent. The owner later unlists the solution: it leaves the public results at once and stays a candidate for an operator matching a use case. An operator takes it down by rejecting it: it leaves the index altogether.

- _An event is lost_ (the process stops between commit and indexing): the event publication registry keeps the publication and it is delivered again; a nightly comparison repairs anything else.
- _The index is empty_ (first deployment, or a rebuilt database): the comparison fills it.
- _A query is malformed or hostile_ (operators, quotes, very long text): it is parsed as web search syntax, capped in length, and never reaches `to_tsquery` raw.

**Glossary.** The terms of the domain model's glossary hold. This slice adds:

| Term              | Meaning                                                                                                                                                                                                               |
| ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Search document   | One indexed item: its kind, its id in the owning module, the text that is searched and the card that is shown                                                                                                         |
| Card              | The plain text that describes an item in a few lines: the answer of search, and later what an embedding and an AI tool read                                                                                           |
| Public            | What any visitor may see: a published program; an approved and listed solution or talent profile                                                                                                                      |
| Matching-eligible | An approved solution that its owner has unlisted: never in public results, still a candidate when an operator matches a use case (brief, "approved, unlisted solution remains eligible for formal use-case matching") |

**Events, commands and read models.**

| Fact                                  | Published by   | When                                                                                                                                                     |
| ------------------------------------- | -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ProgramChanged(programId)`           | `program`      | `ProgramAdministration.save`, `publish` and `unpublish`                                                                                                  |
| `SolutionChanged(solutionId)`         | `solution`     | `SolutionService.save` and `delete`; `SolutionAdministration.approve` and `reject`; any change to a solution's customer deployments that the card counts |
| `TalentProfileChanged(profileId)`     | `talent`       | `TalentService.save`; `TalentAdministration.approve` and `reject`                                                                                        |
| `OrganizationChanged(organizationId)` | `organization` | `OrganizationService.save`, which changes the name and country a solution's card shows                                                                   |

One event per module, named for what changed and carrying only the id. The listener reads the item again through the owner's published API and decides alone whether it is public, matching-eligible or gone, so the order of events, a duplicate or a late delivery never leaves the index wrong. The read model is `matching_search_document`, a projection that `matching` alone writes.

**Owner of data and rules.** Each module stays the source of truth of its items and of whether they are public. `matching` owns the index, the rule of what enters it, the ranking, and the comparison that repairs it.

**Communication.** One-way: `program`, `solution`, `talent` and `organization` publish facts and expose a read of one item by id for indexing; `matching` listens and reads. None of them knows `matching`. The listener runs after the source transaction commits, in its own transaction (`@ApplicationModuleListener`), so a failure to index never undoes an approval, and the JDBC event publication registry keeps the publication until indexing succeeds.

## Decisions

| Decision                    | Choice                                                                                                                                                                              | Why                                                                                                                                                                                                    |
| --------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Where the search lives      | In the `matching` module, as the domain model planned: the index is the base of database matching and of the Phase 2 MCP tool                                                       | One index for search, matching and AI; no second store                                                                                                                                                 |
| Engine                      | PostgreSQL only: full-text search and trigram now, pgvector later, fused by reciprocal rank in one SQL statement                                                                    | A few thousand short public items. MemoryOS needs OpenSearch for millions of chunks with per-document access; nothing here does ([research](../../../research/2026-10-06-search-references.md))        |
| How the index stays in step | Events from the owning modules, delivered after commit through the JDBC event publication registry, plus a nightly comparison and a full rebuild                                    | Spring Modulith's recommended way for modules to interact; MemoryOS and GitLab index from recorded changes the same way. A database trigger, odd-platform's choice, would read another module's tables |
| What enters the index       | Public items, and approved solutions that are unlisted, marked `listed = false`. Drafts, submissions, rejected and deleted items never enter                                        | Public search, the MCP tool and every query that serves a visitor filter `listed`; database matching reads both. Nothing a visitor must not see is in the table, so a faulty query cannot show a draft |
| Unlisted talent             | Not indexed for now                                                                                                                                                                 | The brief keeps only unlisted solutions eligible for matching; asked in BEY-41                                                                                                                         |
| Text configuration          | `simple`, with `unaccent` wrapped in an `IMMUTABLE` function so a generated column can use it                                                                                       | Vietnamese has no PostgreSQL stemmer and English stemming mangles it; unaccent lets "viet nam" find "Việt Nam"                                                                                         |
| Weights                     | Title A; organization, partner or headline B; industries, focus areas, roles, skills and type C; summary and the rest of the card D                                                 | The weights odd-platform gives names over descriptions, adapted to these kinds                                                                                                                         |
| Query parsing               | `websearch_to_tsquery` on the unaccented query, the last word also matched as a prefix, and trigram similarity on titles; the query is at most 100 characters and is never logged   | Raw `to_tsquery` turns user text into parse errors; prefix matching finds a word being typed; trigram finds typos (GitLab's reason for it)                                                             |
| Ranking                     | Reciprocal rank fusion (k = 60) of the full-text ranking and the trigram ranking, each over a pool of four times the page; the vector ranking joins the same fusion in the AI slice | One ranking that does not depend on comparable scores, already proven in the references                                                                                                                |
| Counts per kind             | Computed by the same query over the full match, before the kind filter                                                                                                              | The tabs show every kind's count whatever tab is open                                                                                                                                                  |
| Paging                      | Offset pages of 12, at most 50 pages                                                                                                                                                | Relevance has no stable key to page by; the depth cap follows odd-platform                                                                                                                             |
| Card text                   | Built by `matching` from the owner's read model, stored on the row with a content hash                                                                                              | Search answers without calling four modules; the hash tells when an embedding must be recomputed                                                                                                       |
| Address                     | `GET /api/matching/search?q=&kind=&page=`, public, no session                                                                                                                       | Modules own their paths; search answers visitors                                                                                                                                                       |
| The web page                | `/search` in the web application, built from the approved drawing, `noindex`                                                                                                        | A results page is not a page search engines should index                                                                                                                                               |
| Kinds are a closed list     | `program`, `solution`, `talent`; `use_case` added with its module                                                                                                                   | Each kind has its own read, card and visibility rule                                                                                                                                                   |

### The AI slice, designed here and built after BEY-21

| Decision                        | Choice                                                                                                                                                                                                                                                                                                                                                                                                           | Why                                                                                                                                                                            |
| ------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Provider                        | OpenAI, the key GenAI Fund is providing, through `spring-ai-starter-model-openai`; only the embedding model is enabled until chat is needed                                                                                                                                                                                                                                                                      | One key for embeddings and the matching LLM. The model and its dimensions are chosen in BEY-21: at most 2,000 dimensions, or shortened with `dimensions`, so HNSW can index it |
| Storage                         | `matching_embedding` beside the search document: field, model, dimensions, nullable vector, content hash, status, attempts, next attempt, last error code                                                                                                                                                                                                                                                        | The model is known for every vector, so a new model re-embeds without a migration; the vector is nullable, so an item is found by text before its embedding exists             |
| Index                           | HNSW with `vector_cosine_ops` from the start, as a partial index `where listed` for public search, iterative scans enabled; the vector branch is written so the planner uses it, checked with `EXPLAIN` in a test                                                                                                                                                                                                | The filtering pitfalls of approximate indexes in the pgvector README                                                                                                           |
| Pipeline                        | The listener only marks an item as needing an embedding when its content hash changed. A `@Scheduled` job every minute takes a batch with `for update skip locked`, embeds it in one request, and backs off per row on failure                                                                                                                                                                                   | The model is slow, external, rate-limited and paid. GitLab batches its indexing the same way                                                                                   |
| Spring AI usage                 | `EmbeddingModel.call(EmbeddingRequest)` with `metadata-mode: none` and the dimension fixed in configuration; the SDK's own `max-retries` low for the job, none for the query; on any failure at query time, search falls back to text and says so                                                                                                                                                                | Read from the Spring AI 2.0.1 sources: retries come from the OpenAI SDK, not `spring-ai-retry`; `dimensions()` calls the API; metadata is embedded by default                  |
| Not used                        | `PgVectorStore`, `VectorStore`, `spring-ai-retry`                                                                                                                                                                                                                                                                                                                                                                | No full-text, a fixed table, dimensions bound to the table; the OpenAI module does not use the retry module                                                                    |
| Chatbot, if one comes           | A `DocumentRetriever` that calls the search service and keeps `listed`, for `RetrievalAugmentationAdvisor`                                                                                                                                                                                                                                                                                                       | Spring AI 2.0.1's RAG takes a retriever; `QuestionAnswerAdvisor`'s module stops at 2.0.0-M8                                                                                    |
| Operators' Search and AI screen | Counts indexed per kind against the sources, pending and failed embeddings with their codes, the model in use; rebuild the index and retry failures; the provider, model and API key entered by an operator, the key encrypted with Spring Security's AES-GCM and a master key held as a deployment secret, and a test of the connection. Each action audited. MemoryOS's settings without its index generations | Operators run the search without the team; at this size a model change re-embeds in place                                                                                      |
| MCP, Phase 2                    | One read-only, non-destructive `@McpTool` delegating to the search service, stateless                                                                                                                                                                                                                                                                                                                            | It needs nothing built in advance                                                                                                                                              |

## The addresses

| Request                                                                   | Answer                                                                                                                                                                                                                             |
| ------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /api/matching/search?q=voice%20agent`                                | `200` with `counts` (`all`, `program`, `solution`, `talent`), the first page of `items` (kind, slug, title, subtitle, summary, facets, and for a program its phase and days), `page`, `pageSize` and `total` for the selected kind |
| `GET /api/matching/search?q=voice&kind=solution&page=2`                   | The same, narrowed to one kind                                                                                                                                                                                                     |
| `q` missing, empty, longer than 100 characters, or `page` outside 1 to 50 | `400` `REQUEST_INVALID` with a pointer to the member                                                                                                                                                                               |

## Data

| Table                           | Columns                                                                                                                                                                                                                                                                                                                                           |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `event_publication`             | The Spring Modulith 2 schema for PostgreSQL, created by Flyway; completed publications are deleted                                                                                                                                                                                                                                                |
| `matching_search_document`      | `kind`, `item_id` (primary key together); `slug`, `title`, `subtitle`, `card`, `facets jsonb`, `listed`, `starts_on`, `ends_on` for programs, `content_hash`, `indexed_at`; `search_vector tsvector` generated from the weighted, unaccented fields; a GIN index on it, a trigram index on the unaccented title, and an index on `(kind, listed)` |
| `matching_embedding` (AI slice) | `kind`, `item_id`, `field`, `model`, `dimensions`, `embedding vector(n)` nullable, `content_hash`, `status`, `attempts`, `next_attempt_at`, `error_code`, `embedded_at`                                                                                                                                                                           |

## What the owning modules add

Each change is a few lines in the owner's module, made in its own pull request and reviewed by its owner:

| Module                | Published read for indexing                                                                                                                               | Events                 |
| --------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------- |
| `program` (this team) | `ProgramService.indexed(UUID)`: the published program with its card fields, or empty; `ProgramService.indexedAll()` for the comparison                    | `ProgramChanged`       |
| `solution` (Việt)     | `SolutionDirectory.indexed(UUID)`: an approved solution with its card fields, its organization's name and country, and `listed`, or empty; `indexedAll()` | `SolutionChanged`      |
| `talent` (Việt)       | `TalentDirectory.indexed(UUID)`: an approved, listed profile with its card fields, or empty; `indexedAll()`                                               | `TalentProfileChanged` |
| `organization` (Việt) | `OrganizationDirectory`'s existing read of names is enough                                                                                                | `OrganizationChanged`  |

`matching` gains `allowedDependencies = { "program", "solution", "talent", "organization" }`. None of them depends on `matching`, so no cycle appears; `ModulithArchitectureTest` adds `matching` to its list.

## Conventions this introduces

Recorded in the [backend guide](../../../guidelines/backend.md) when the first event lands:

- A fact another module may react to is a public record in the publishing module's root package, named in the past tense, carrying identifiers only.
- It is published from the application service, inside the transaction, right after the state change.
- A listener in another module is a package-private `@ApplicationModuleListener`; it reloads what it needs through the publisher's published API and is idempotent.
- The JDBC event publication registry stores publications; outstanding ones are republished on restart while one instance runs.

## Failure behavior

| Failure                                   | Behavior                                                                                                                                        |
| ----------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| Indexing fails after an approval          | The approval stands; the publication stays incomplete and is delivered again; the item is missing from search until then, never wrongly present |
| An item stops being public                | The listener removes it, or marks a solution unlisted, in the same delivery                                                                     |
| The index and the sources disagree        | The nightly comparison inserts, updates and removes rows, and logs `matching.search_index.repaired` with counts                                 |
| The embedding provider is down (AI slice) | Search ranks by text and the answer says so; the job backs off per row                                                                          |

## Verification

- Integration tests on PostgreSQL: Vietnamese with and without accents, a typo, a prefix, a mixed list in the expected order, counts per kind, an unlisted solution absent from public search, a hostile query answered without error.
- Spring Modulith `Scenario` tests: approving, unlisting and rejecting a solution, publishing and unpublishing a program, and renaming an organization each reach the index.
- The comparison repairs a deleted row and an extra row.
- Web end-to-end: the All tab, a kind tab, no results, the query kept after a reload, at desktop and mobile widths with axe.
