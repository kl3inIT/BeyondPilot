# AI providers and the search index in Admin

Status: done on 6 October 2026, live on staging; accepted the same day, with the drawing approved the same day (Figma section "Admin — AI: Providers and Search index"). Tracked in Linear as BEY-72. It is the operators' screen the [search design](../bey-65-search/design.md) left for the AI slice.

## What changes

- Operators connect the embedding provider and choose the model in Admin › AI › Providers, a screen with a tab per purpose: Embedding now, Chat when a feature needs one. Nothing about the provider is read from the environment any more; the key is the only secret, sealed in the database.
- Admin › AI › Search index shows what search can find, how much of it is embedded, what the provider refused, and the state of semantic search, which operators can turn off.
- The admin sidebar gains an AI group between Review and System.

## Decisions

| Decision                    | Choice                                                                                                                                                                                             | Why                                                                                                                                                                                               |
| --------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Where providers live        | Table `ai_provider` with a `purpose` (`embedding` only), owned by `search` until a second feature uses a provider; then it moves to its own module with its rows                                   | One feature uses it today; no module is created ahead of its second user                                                                                                                          |
| Vendors                     | OpenAI and OpenRouter, both through the OpenAI API, each reached only at its own API address                                                                                                       | The server calls the address with the key from inside the network: a free address would let an operator reach an internal host or the cloud's metadata endpoint, or send the stored key elsewhere |
| Keys                        | AES-GCM with `BEYONDPILOT_AI_ENCRYPTION_KEY` (32 bytes, the host's `ai-encryption-key`), never returned, kept on a change only while the vendor is the same; Keep, Replace or Remove in the editor | The email providers' rule (BEY-68) and MemoryOS's provider editor                                                                                                                                 |
| The client in use           | Built from the stored provider and model, built again after a change commits, without a restart; one instance runs, so the change made is the only one                                             | MemoryOS's search generations rebuild their clients the same way, without the generations: at this size a model change re-embeds in place                                                         |
| Choosing a model            | The provider embeds a test sentence first; a provider in use cannot be deleted                                                                                                                     | A choice that cannot embed would stop semantic search for everyone                                                                                                                                |
| Turning semantic search off | Search matches keywords only and the job sends nothing; on again, it embeds what changed meanwhile                                                                                                 | An operator can stop the cost or a misbehaving provider without the team                                                                                                                          |
| Audit                       | Connecting, changing and deleting a provider; choosing the model; turning semantic search on or off; rebuilding; retrying                                                                          | Each changes what visitors find or what is sent outside                                                                                                                                           |
| New dependencies            | `search` → `identity` (the operator check) and `audit`                                                                                                                                             | The service authorizes and records its own changes, as every admin service does                                                                                                                   |
